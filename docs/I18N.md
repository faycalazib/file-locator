# Internationalization (i18n)

> Spec: [`goal.md`](../goal.md) §5bis. Supported languages: **en** (reference and fallback), **fr**, **es**, **ar** (right-to-left).

## Files

- `ui/src/lib/i18n/locales/{en,fr,es,ar}.json`: the message catalogs.
- `ui/src/lib/i18n/index.svelte.ts`: the runtime, which exports `t()`, `i18n`, `LOCALES` and the `format*` helpers.
- `scripts/i18n-check.mjs`: the check behind `pnpm i18n:check`.

## Using translations in a component

```svelte
<script lang="ts">
  import { t, formatBytes, formatRelative } from '../i18n/index.svelte';
</script>

<h2>{t('rail.sites')}</h2>
<span>{t('results.matches', { count: 7 })}</span>
<span>{formatBytes(hit.sizeBytes)} · {formatRelative(hit.modified)}</span>
```

- **Typed keys.** `MessageKey` is generated from `en.json`, so an unknown key is a TypeScript error. For a dynamic key, use a template literal cast: `` `filters.kinds.${kind}` as MessageKey ``.
- **Reactivity.** Calling `t()` in a template re-renders when the language changes.
- **Placeholders.** Write them as `{name}`. Numbers are formatted in the active locale.
- **Plurals.** Use an object with ICU categories: `{ "one": "...", "other": "..." }`.
  - Arabic needs `zero`, `one`, `two`, `few`, `many` and `other`.
  - For fr and es, `many` (millions, as in "1 000 000 de…") is recommended but optional.
- **No hardcoded text.** Only data (file names, names chosen by the user) and universal symbols (`Aa`, `.*`, `CSV`) are left untranslated.

## Right-to-left (Arabic)

- `i18n.set()` updates `<html lang dir>`. The 3-zone grid mirrors itself automatically.
- Use **CSS logical properties only**: `margin-inline-start`, `border-inline-start`, `inset-inline-*`, `padding-inline`. Never use `left` or `right`.
- **Paths, code and regex** always get `dir="ltr"` and the `.ltr-isolate` class.
- **Document excerpts** get `dir="auto"` and `unicode-bidi: plaintext`, so each paragraph takes its own direction.
- **Directional icons** (chevrons) get the `flip-rtl` class, set in `Icon.svelte` through `DIRECTIONAL`.
- **Typography.** `:root:lang(ar)` puts Baloo Bhaijaan 2 first in the font stack, for titles and body text alike ("Colored pencils" theme). The PROSPECTOR brand stays in Latin letters and LTR.
- **Numbers.** Arabic uses Latin digits (`ar-u-nu-latn`) so they match the paths. This can be changed in `INTL_TAG`.

## Language selection

1. Explicit choice, stored in `localStorage` under `prospector.locale` (moves to `tauri-plugin-store` at Étape 1).
2. Otherwise, `navigator.languages` (the OS language).
3. Otherwise, `en`.

For screenshots, `?lang=ar` forces the language without storing it.

## Adding a language

1. Copy `en.json` to `<code>.json` and translate it, covering every plural category of the language.
2. Add `<code>` to the `Locale` type, `LOCALES`, `catalogs` and `INTL_TAG` in `index.svelte.ts`.
3. If the language is written right to left, set `dir: 'rtl'`, and embed a suitable font if needed (an exception to goal.md §5, to be approved).
4. Run `pnpm i18n:check`, then `pnpm check`.

## Backend

The Rust code never sends translated text: it sends **codes**, which the UI translates.

- Engine errors (`CoreError`) and app-shell errors (`AppError`) cross the bridge as `{ code, params }`. `AppError::Core` wraps a `CoreError`; `errorCode()` in `api.ts` unwraps it.
- Each code has an `errors.<code>` key in all 4 languages (`rootUnavailable`, `indexBusy`, `fileNotIndexed`, `openFailed`…). `notices.error(e)` shows it; unknown codes fall back to `errors.unknown`.
- The skip reasons for unreadable files (`binary`, `corrupt`, `encrypted`…) are counters shown as "N unreadable files".
- Native texts (OS menus, tray) will be translated on the Rust side from the same JSON files.
